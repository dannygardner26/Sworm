v0.2.0 — spatial agent orchestration

installation

sworm requires node.js ≥ 20 and runs on windows 11. clone and install:

$ git clone https://github.com/dannygardner26/Sworm.git
$ cd Sworm
$ npm install
$ npm run build

after building, the sworm command is available via npm run dev during development or node dist/cli/index.js in production.

quick start

$ sworm deploy pilot # deploy a formation
$ sworm run claude # quick-launch claude code
$ sworm run shell # quick-launch a terminal
$ sworm list # see available formations
$ sworm status # check active worms
$ sworm kill # tear down everything

run sworm with no arguments to see available formations and active worms at a glance.

cli — deploy

deploy a named formation from the formations/ directory.

$ sworm deploy <formation>
$ sworm deploy pilot --force # kill existing worms first
$ sworm deploy pilot --dry-run # preview window positions
optiondescription
--forcekill all active worms before deploying
--dry-runshow computed positions without spawning windows

omit the formation name to see a list of available choices.

cli — run

quick-launch a single worm without writing a yaml file.

$ sworm run claude # claude code, full screen
$ sworm run claude -z left-half # claude code, left half
$ sworm run shell # windows terminal
$ sworm run code . # vs code on current dir
$ sworm run https://github.com # open url in chrome
$ sworm run notepad.exe # any executable
optiondescription
-m, --monitortarget monitor reference (default: primary)
-z, --zoneposition zone (default: full)

cli — kill

tear down active worms — all at once, by formation name, or by individual worm id.

$ sworm kill # kill all active worms
$ sworm kill pilot # kill by formation name
$ sworm kill --id editor # kill a specific worm

cli — list

show all available formations with descriptions and worm counts.

$ sworm list

cli — status

display the current state of all active worms — their ids, types, status, and assigned numbers.

$ sworm status

cli — monitors

list all connected monitors with their bounds, work areas, and scale factors. useful for debugging multi-monitor formations.

$ sworm monitors

cli — voice

manage voice activation — setup whisper, start listening, or check status.

$ sworm voice setup # download whisper.cpp + model
$ sworm voice listen # start push-to-talk + wake word
$ sworm voice listen --no-wake # hotkey-only mode
$ sworm voice listen --bridge # http bridge mode
$ sworm voice status # show voice config

formation yaml schema

formations are yaml files in the formations/ directory that declare which worms to deploy and where.

name: pilot
description: "primary dev formation"
mode: normal # normal | wallpaper
monitors: # optional monitor aliases
dev: primary
ref: right
grid: # optional grid config
columns: 12
rows: 6
gap: 4
hooks: # optional lifecycle hooks
pre: ["echo deploying"]
post: ["echo done"]
worms:
- id: my-worm
type: claude
monitor: primary
position:
zone: left-half
params: {}

positioning

each worm has a position field that supports three modes:

zone positioning

predefined screen regions. the simplest way to place windows.

zonedescription
fullentire work area
left-halfleft 50%
right-halfright 50%
top-halftop 50%
bottom-halfbottom 50%
top-lefttop-left quadrant
top-righttop-right quadrant
bottom-leftbottom-left quadrant
bottom-rightbottom-right quadrant
left-thirdleft 33%
center-thirdcenter 33%
right-thirdright 33%
position:
zone: left-half

grid positioning

place worms on a virtual grid. configurable columns, rows, and gap.

position:
grid:
col: 0 # column index (0-based)
row: 0 # row index (0-based)
colSpan: 6 # span columns (default: 1)
rowSpan: 3 # span rows (default: 1)

absolute positioning

pixel or percentage-based coordinates relative to the monitor work area.

position:
absolute:
x: 0 # pixels or "50%"
y: 0
width: "50%"
height: "100%"

monitor references

the monitor field on each worm specifies which display to target.

referencedescription
primarythe primary display
leftleftmost monitor
rightrightmost monitor
toptopmost monitor
bottombottommost monitor
index:Nmonitor by index (0-based)

you can also define monitor aliases in the formation's monitors map and reference those aliases in worm configs.

grid system

the optional grid config on a formation sets up a virtual grid for precise layouts.

propertydefaultdescription
columns12number of columns
rows6number of rows
gap4gap between cells (px)

worm types

each worm has a type that determines what it spawns and how it finds its window.

idevs codefolder, workspace, files
appbrowser (chrome, edge, firefox, brave)app, url, profile, args
ai-agentllm agent with tool useprovider, model, repo, prompt, systemprompt, branch
genericany executableexecutable, args

worm — claude

launches claude code in a terminal window. supports git worktrees for isolated branches.

paramtypedescription
repostring (required)repository path, or "." for cwd
shell"wt" | "cmd" | "powershell"terminal to use (default: wt)
branchstringcreate a git worktree for this branch
worktreePathstringcustom worktree directory
initialPromptstringinitial prompt to pass to claude

worm — ide

opens vs code with --new-window.

paramtypedescription
folderstringfolder to open
workspacestring.code-workspace file to open
filesstring[]specific files to open

worm — app

launches a browser window. chromium browsers get --new-window and profile support.

paramtypedescription
appstring (required)browser name: chrome, edge, firefox, brave, or full path
urlstringurl to open
profilestringbrowser profile directory (chromium only)
argsstring[]additional command-line arguments

worm — ai-agent

spawns an autonomous ai agent in a terminal. the agent runs in a loop using llm tool use to read/write files and execute commands.

paramtypedescription
providerstring (required)provider name from providers.yaml
modelstringoverride model
repostring (required)repository path
promptstring (required)task for the agent
systemPromptstringcustom system prompt
branchstringcreate a git worktree
shell"wt" | "cmd" | "powershell"terminal to use

worm — generic

launches any executable. window detection uses a before/after snapshot approach.

paramtypedescription
executablestring (required)path or name of executable
argsstring[]command-line arguments

agent tools

ai agents have access to four built-in tools, sandboxed to the working directory:

tooldescription
file_readread the contents of a file
file_writewrite content to a file (create or overwrite)
file_listlist files in a directory (optionally recursive)
shell_execexecute a shell command (30s timeout)
security: all file paths are validated to stay within the working directory. the agent cannot escape its sandbox.

agent configuration

agent runtime settings:

settingdefaultdescription
maxIterations50maximum tool-use loop iterations
maxTokens4096max tokens per llm response

voice control

sworm supports hands-free operation via whisper-powered speech recognition. two activation modes:

  • push-to-talk — hold a hotkey (default: ctrl+shift+space) and speak
  • wake word — say "hey sworm" to activate (configurable)

setup

run sworm voice setup to download whisper.cpp and the tiny.en model automatically. this configures ~/.sworm/config.yaml with the correct paths.

voice commands

supported voice commands (filler words like "please", "um", "just" are automatically stripped):

sayaction
"deploy pilot"deploy formation
"switch to debug"deploy formation
"kill all"kill all worms
"kill editor"kill specific worm
"status"show status
"focus on editor"focus a worm
"agent 2"focus worm #2
"expand agent 1"fullscreen worm #1
"fullscreen 3"fullscreen worm #3
"list formations"list available formations
"minimize all"send all to back
"show worms"toggle visibility

hotkeys

global win32 keyboard shortcuts are registered automatically when running. configure bindings in ~/.sworm/config.yaml.

actiondescription
toggle-visibilityshow/hide all worms
focus-wormfocus worm by number
kill-allkill all worms
deploy-defaultdeploy the pilot formation
voice-activatestart push-to-talk recording
key format: modifier keys are ctrl, shift, alt, win. combine with +, e.g. ctrl+shift+s. supports alphanumeric keys, f1-f8, space, enter, escape, tab.

configuration — ~/.sworm/config.yaml

global settings file. generated automatically on first use or via sworm voice setup.

general:
defaultFormation: pilot
formationsDir: "./formations" # custom path
theme: dark # dark | light
voice:
enabled: false
pushToTalk:
enabled: true
hotkey: "ctrl+shift+space"
wakeWord:
enabled: false
phrase: "sworm"
whisper:
binaryPath: ""
modelPath: ""
sampleRate: 16000
recorder: sox # sox | ffmpeg
pttTimeout: 5000
feedback:
chimeOnListen: true
chimeOnAcknowledge: true
hotkeys:
enabled: true
bindings:
- key: "ctrl+shift+s"
action: toggle-visibility

configuration — ~/.sworm/providers.yaml

define llm providers for ai agents. api keys can reference environment variables via ${ENV_VAR} syntax.

providers:
claude:
type: anthropic
apiKey: "${ANTHROPIC_API_KEY}"
defaultModel: claude-sonnet-4-20250514
gpt:
type: openai
apiKey: "${OPENAI_API_KEY}"
defaultModel: gpt-4o
gemini:
type: gemini
apiKey: "${GEMINI_API_KEY}"
local:
type: ollama
baseUrl: "http://localhost:11434"
defaultModel: llama3
defaults:
provider: claude
model: claude-sonnet-4-20250514
fielddescription
typeprovider type (anthropic, openai, azure-openai, gemini, bedrock, ollama, claude-code)
apiKeyapi key or env var reference
baseUrlcustom api endpoint
regionaws region (bedrock)
deploymentazure deployment name
defaultModeldefault model for this provider
